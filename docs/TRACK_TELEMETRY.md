# Сравнение трекинга с телеметрией

`python research/track_telemetry.py` проверяет исходный Lite на 52–58 с.

```powershell
python research/track_telemetry.py "F:\36\54-56-DJI_20260517170526_0020_D.MP4" --start 52 --end 58 --exclude 54 56
```

Для другого участка укажите также `--exclude начало конец`: это подозрительный
интервал, который исключается из подбора соглашения об осях. Оставьте несколько
секунд контекста по краям. На вход нужен исходный DJI MP4 с собственной телеметрией.
Видео и телеметрия не изменяются; рендер не выполняется.

Результаты в `artifacts/analysis/<имя>_tracking` (или `--out папка`):

- `comparison.png`: три компоненты вращения и величина расхождения.
- `comparison.csv`: время середины пары, номера кадров с нуля, число точек,
  поддержка модели, вращение по видео/телеметрии и их разность.
- `report.json`: параметры объектива, осей и времени, кандидаты расхождений.
- `tracks.npz`: координаты соответствующих точек для повторного анализа.

По умолчанию изображение уменьшается до 25%, точки сравниваются через 5 кадров
(100 мс при 50 fps), с шагом один кадр. Настройки: `--scale 0.5`, `--gap 1`.
`--reuse-tracks` повторяет расчёт по сохранённым точкам без декодирования видео.
`--offset-ms 100` читает телеметрию на 100 мс позже стандартного момента;
сдвиг автоматически не подбирается. Стандартный момент — время кадра плюс
половина времени считывания сенсора, как в ранее проверенном нативном экспорте.

Трекинг Lucas–Kanade проверяется обратным проходом. Координаты исправляются по
fisheye-параметрам конкретного файла. Essential matrix + recoverPose оценивают
вращение совместно с направлением перемещения. Масштаб перемещения неизвестен.
Слабая поддержка, практически чистое вращение или слишком малый параллакс дают
пропуск оценки. Серая линия отдельной модели только вращения чувствительна
к перемещению дрона и служит дополнительной диагностикой.

Компоненты X/Y/Z — векторы относительного вращения в осях изображения,
не столбцы Euler Pitch/Yaw/Roll из предыдущих экспериментов. Знаки и порядок
компонент телеметрии подбираются по контексту, без использования подозрительного
интервала. Большая ошибка этого подбора означает, что сравнению нельзя доверять
как точному измерению дефекта.

Пики — кандидаты для проверки, не доказанные ошибки телеметрии. Плоская сцена,
смаз, движение объектов и rolling shutter могут искажать оценку даже при большом
числе согласованных точек. Построчная компенсация rolling shutter не выполняется.
Измеряется среднее вращение за пару кадров, поэтому пики короче `gap/fps` размываются.

Описание геометрии и функций: [документация OpenCV](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html).
Зависимости: `opencv-python`, `numpy`, `scipy`, `matplotlib` и модули этого проекта.
